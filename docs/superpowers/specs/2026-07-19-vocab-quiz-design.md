# 영단어 퀴즈 웹앱 — PRD

- 작성일: 2026-07-19 (개정: 2026-07-20 — 단어집 다중화 + 회독 모드 추가)
- 상태: 초안 (사용자 리뷰 대기)

## 1. 개요 / 목적

이미 단어를 다 외운 학생(사용자 본인)이 여러 단어집(현재는 `HS_complete.txt`, Day 1~40, 총 1200개, Day당 30개)의 단어를 얼마나 알고 있는지 스스로 점검하기 위한 개인용 퀴즈 웹앱.

두 가지 모드를 제공한다.
- **자유 퀴즈 모드**: Day 범위와 문제 수를 지정하면 그 범위에서 무작위로 단어를 1회성으로 출제.
- **회독 모드**: 같은 범위를 반복해서 훑으며, 맞힌 단어는 제외하고 틀린 단어는 다음 회독으로 넘겨 계속 재출제. 오래 붙들고 있는(계속 틀리는) 단어를 자동으로 추려서 보여준다.

두 모드 모두 사용자가 한글 뜻 또는 영어 예문으로 답하면 Claude API가 정답 여부와 이유를 판정한다.

## 2. 목표 / 비목표

**목표**
- 단어집을 여러 개 등록할 수 있고, 각 단어집은 독립적으로 관리된다 (지금은 `HS_complete` 하나뿐이지만 나중에 늘어날 수 있음).
- **자유 퀴즈**: Day 범위(예: Day 3, 또는 Day 1~Day 10)와 문제 수(1~30)를 지정해 무작위 1회성 퀴즈를 진행할 수 있다.
- **회독 모드**: 단어집 + Day 범위를 지정해, 맞힌 단어는 제외하고 틀린 단어만 반복해서 재출제하는 방식으로 여러 회독에 걸쳐 익힐 수 있다. 계속 틀리는 "취약 단어"를 자동으로 추려서 알려준다.
- 자유 형식 답변(한글 뜻, 영어 예문 등)을 Claude가 채점하고 간단한 이유를 알려준다.
- 퀴즈 결과와 회독 진행 상태가 서버에 영구 저장되어, 나중에 다시 접속해도 이어서 진행할 수 있다.

**비목표 (이번 범위에서 제외)**
- 로그인/계정/멀티유저 지원 — 본인 혼자 쓰는 도구.
- 앱 내 단어집 업로드/편집 UI — 단어 데이터는 시드 스크립트로 주입(단어집이 늘어나도 스크립트 재실행 방식 유지).
- 회독 간 시간 간격을 고려한 간격 반복(spaced repetition) 스케줄링(예: "며칠 뒤에 다시 물어보기") — 이번 회독 모드는 시간이 아니라 "맞았는지 여부"만으로 다음 회독 여부를 정한다.

## 3. 사용자 & 사용 시나리오

단일 사용자(본인)가 브라우저로 접속해:

**자유 퀴즈**
1. 단어집 선택 + Day 범위 선택 + 문제 수 입력.
2. "퀴즈 시작" → 해당 범위에서 무작위로 단어가 한 번에 하나씩 출제됨.
3. 자유 텍스트로 답변 입력 후 제출 → Claude가 정답 여부(O/X) + 이유를 즉시 보여줌.
4. 모든 문제를 마치면 세션 요약 표시.

**회독 모드**
1. 단어집 선택 + Day 범위 선택 + 이번 세션에서 풀 문제 수 입력. 화면에 현재 진행 상태 요약("전체 단어수/맞은수/틀린수/대기")이 보인다.
2. "회독 시작" → 아직 이번 회독에서 맞히지 못한 단어들(처음 보는 단어 + 틀렸다가 재도전 대기 중인 단어) 중 무작위로 지정한 개수만큼 출제.
3. 맞히면 그 단어는 이번 회독에서 더 이상 나오지 않는다. 틀리면 큐 뒤쪽에 다시 끼워 넣어(바로 다음 문제로 반복되지 않게) 같은 세션 안에서 다시 도전한다.
4. 한 단어를 첫 시도에 맞히면 "졸업"(더 이상 어떤 회독에도 안 나옴), 틀렸다가 맞히면 다음 회독으로 이월.
5. 세션 종료 시 정답/오답 수, 졸업한 단어 수, 다음 회독으로 넘어간 단어 수를 요약. 3회 이상 연속으로 회독을 넘기며 틀린 "취약 단어"가 있으면 별도로 안내.
6. "기록" 페이지에서 과거 세션과 취약 단어 목록을 다시 볼 수 있음.

## 4. 아키텍처

- **프레임워크**: Next.js (App Router, TypeScript), Tailwind CSS, Vercel 배포.
- **DB**: Vercel Marketplace의 Neon Postgres. 스키마 관리는 Drizzle ORM.
- **AI 연동**: Vercel AI SDK를 통해 AI Gateway 경유로 Claude 모델 호출(`"anthropic/claude-..."` 형식의 모델 문자열). 채점은 `generateObject` + zod 스키마로 구조화된 JSON(`{ correct: boolean, feedback: string }`)을 받아 파싱 오류 없이 처리.
- **인증**: 없음 (본인 전용 개인 도구).

## 5. 데이터 모델

```sql
wordbooks
  id     serial PRIMARY KEY
  name   text NOT NULL UNIQUE      -- 예: "HS_complete"

words
  id            serial PRIMARY KEY
  wordbook_id   int NOT NULL REFERENCES wordbooks(id)
  day           int NOT NULL              -- 단어집 내부 기준 Day 번호
  word          text NOT NULL
  UNIQUE (wordbook_id, day, word)

word_progress                      -- 회독 모드 전용 진행 상태 (단어별 독립 추적)
  word_id            int PRIMARY KEY REFERENCES words(id)
  round              int NOT NULL DEFAULT 1        -- 이 단어가 현재 속한 회독 번호
  status             text NOT NULL DEFAULT 'pending'  -- 'pending' | 'correct'
  missed_this_round  boolean NOT NULL DEFAULT false   -- 이번 회독에서 한 번이라도 틀렸는지
  wrong_rounds       int[] NOT NULL DEFAULT '{}'    -- 틀렸던 회독 번호들의 누적 기록 (예: {1,2} = 1,2회독에서 틀림)
  retired            boolean NOT NULL DEFAULT false -- true면 이후 어떤 회독에도 재출제 안 함
  updated_at         timestamptz NOT NULL DEFAULT now()

attempts
  id           serial PRIMARY KEY
  session_id   uuid NOT NULL        -- 한 번의 퀴즈 세션(여러 문제)을 묶는 값
  word_id      int NOT NULL REFERENCES words(id)
  mode         text NOT NULL        -- 'free' | 'review'
  round        int                  -- mode='review'일 때만 값 존재 (그 시점의 회독 번호)
  user_answer  text NOT NULL
  is_correct   boolean NOT NULL
  feedback     text NOT NULL
  created_at   timestamptz NOT NULL DEFAULT now()
```

- 단어 자체의 "뜻"은 저장하지 않는다 — 채점 시 Claude가 자체 지식으로 판단한다.
- `session_id`는 퀴즈 시작 요청 처리 시 서버에서 생성한 UUID로, 같은 세션에 속한 문제들을 하나로 묶는다. 별도의 `sessions` 테이블은 두지 않는다.
- `word_progress` 행은 해당 단어가 회독 모드에서 처음 출제될 때 `round=1, status='pending'`으로 지연 생성(lazy insert)된다. 자유 퀴즈 모드는 `word_progress`를 전혀 건드리지 않는다.

## 6. 단어 데이터 시드

- 사용자가 단어집별 텍스트 파일 제공 (`[dayNN]` 헤더 + 번호. 단어 형식, 뜻 없음). 현재는 `HS_complete.txt` 하나.
- 개발자(Claude Code)가 파일을 파싱해 `wordbooks`에 해당 단어집을 등록하고 `words`에 단어를 삽입하는 시드 스크립트를 실행. 단어집이 늘어나면 새 파일에 대해 같은 스크립트를 재사용(파일 경로/단어집 이름을 인자로 받도록 작성).
- 앱 내 업로드/편집 UI는 만들지 않는다.

## 7. UI/UX 흐름

**모드 선택 화면**
- "자유 퀴즈" / "회독 모드" 두 버튼으로 진입.

**자유 퀴즈 — 시작 화면**
- 단어집 선택(select).
- Day 범위 선택: "시작 Day"와 "끝 Day" select. 단일 Day는 둘을 같은 값으로.
- 문제 수: 숫자 입력 (1~30, 기본값 5).
- "퀴즈 시작" → 범위 내 단어 중 무작위 비복원 추출(부족하면 있는 만큼만 출제 + 안내 문구).

**자유 퀴즈 — 진행/결과 화면**
- 기존과 동일: 카드 하나씩, 자유 텍스트 입력 → 채점 결과 즉시 표시 → 진행률("3/5") → 세션 요약.

**회독 모드 — 시작 화면**
- 단어집 선택 + Day 범위 선택(자유 퀴즈와 동일한 UI 재사용).
- 이번 세션 문제 수 입력.
- 선택한 범위의 현재 상태 요약 표시: **"전체 단어수 N, 맞은수 X, 틀린수 Y, 대기 Z"** (X+Y+Z=N).
  - 맞은수(X) = `retired=true` (졸업 — 더 이상 재출제 안 됨)
  - 틀린수(Y) = `word_progress` 존재 & `retired=false` (한 번이라도 틀려서 재도전 대기 중이거나, 세션이 끊겨 아직 재도전 전인 단어 포함)
  - 대기(Z) = `word_progress` 미생성 (한 번도 출제된 적 없음)
- "회독 시작" → `retired=false`인 단어(틀린수 + 대기) 중 **가장 작은 회독 번호에 해당하는 단어들만** 후보로 삼아 무작위로 지정 개수만큼 뽑아 세션 큐 구성 (자세한 우선순위 규칙은 8절 참고). 즉 대기(1회독)가 남아있으면 틀린수(2회독 이상)는 섞이지 않고, 대기가 0이 되어야 그다음 회독 단어가 나오기 시작한다.

**회독 모드 — 진행 화면**
- 기존 퀴즈 카드 UI + 상단에 "N회독" 배지, "이번 세션 M/K" 진행률.
- 오답 시: 카드에 "N회독으로 이월 예정" 안내와 함께, 같은 세션 큐의 5~10문제 뒤쪽에 재삽입(바로 다음 문제로 바로 반복되지 않게). 남은 큐가 5문제보다 짧으면 큐 맨 끝에 삽입.
- `wrong_rounds` 길이가 이번에 3 이상이 되면 "취약 단어" 배지 표시.

**회독 모드 — 결과 요약 화면**
- 이번 세션 정답/오답 수, 새로 졸업(맞은수로 이동)한 단어 수, 다음 회독으로 이월(틀린수 유지)된 단어 수.
- 세션 종료 후 갱신된 범위 전체 상태 요약("전체 단어수 N, 맞은수 X, 틀린수 Y, 대기 Z")도 함께 표시.
- 이번 세션에서 새로 취약 단어로 분류된 단어가 있으면 목록 표시.

**기록(History) 페이지**
- 과거 세션 목록 (날짜, 모드, 단어집/Day 범위, 정답 수/전체 문제 수).
- 세션 클릭 시 문제별 상세(단어, 내 답변, 정답 여부, 피드백, 회독 모드면 회독 번호도) 확인.
- "취약 단어" 탭: 단어집별로 `array_length(wrong_rounds,1) >= 3`인 단어 전체 목록, 각 단어가 틀렸던 회독 번호(`wrong_rounds`)도 함께 표시(졸업 여부와 무관하게 계속 조회 가능, 상시 갱신).
- "Day별 현황" 탭: 단어집 선택 시 그 단어집의 Day 1~N 각각에 대해 맞은수/틀린수/대기 개수를 표(또는 리스트)로 표시. 단어 목록까지는 보여주지 않고 개수만(회독 시작 화면에서 범위를 고를 때 어느 Day에 대기가 몰려 있는지 참고용).

## 8. 회독 상태 전이 로직

**출제 대상 선택** (회독 모드, 단어집+Day 범위 지정 시)
- 1차 후보군: 범위 내 단어 중 `word_progress`가 없거나(=아직 미출제, `round=1`로 간주) `status='pending'`인 단어.
- **회독 번호 우선순위**: 1차 후보군에서 가장 작은 `round` 값을 구하고(예: 대기 단어는 1, 틀린수 단어는 2 이상 섞여 있으면 그중 최솟값), 그 최솟값과 `round`가 같은 단어들만 최종 후보 풀로 삼는다. 즉 더 큰 회독 번호(예: 3회독) 단어는 더 작은 회독 번호(예: 2회독) 단어가 이 범위에 하나라도 남아있는 한 출제되지 않는다. 아직 한 번도 안 나온 단어(`round=1`)와 1회독에서 틀린 단어(`round=2`)가 섞여 있으면 항상 `round=1`(대기) 쪽이 먼저 전부 소진된 뒤에야 `round=2` 단어가 나오기 시작한다.
- 최종 후보 풀에서 무작위로 지정 문제 수만큼 뽑아 세션 큐 구성. 후보 풀 크기가 요청 문제 수보다 작으면 있는 만큼만 출제(10절 에러 처리 참고).

**답변마다 처리**
- **정답** → `status='correct'`로 변경(이번 회독에서 재출제 제외).
- **오답** → `status='pending'` 유지, `missed_this_round=true`로 표시. 세션 큐 뒤쪽에 재삽입.

**단어가 `status='correct'`가 되는 순간(=이번 회독을 통과하는 순간) 판단**
- `missed_this_round=false`(첫 시도에 맞음) → `retired=true`로 "졸업" 처리. 이후 어떤 회독에도 다시 나오지 않는다. (`wrong_rounds`는 그때까지 기록을 그대로 남겨둔다 — 이력이므로 지우지 않음.)
- `missed_this_round=true`(틀렸다가 결국 맞음) → 현재 `round` 값을 `wrong_rounds` 배열에 추가(예: 2회독에서 틀렸다면 `wrong_rounds`에 2를 append), `round += 1`, `status='pending'`, `missed_this_round=false`로 리셋(다음 회독 대상).

**취약 단어 판정**
- `array_length(wrong_rounds, 1) >= 3`이 되는 순간(회독을 3번 이상 틀리다가 맞춘 경우) 그 단어를 "취약 단어"로 표시. 이는 종료 조건이 아니라 체크포인트 알림이며, 회독 자체는 계속 이어진다(4회독, 5회독…).
- 후보 풀이 비면(모든 단어가 `retired=true`) 해당 범위는 "완주" 상태로 간주하고 회독 시작 화면에 안내 문구 표시.

**상태 요약 계산** (회독 시작 화면·결과 화면 공통)
- 맞은수 = 범위 내 `retired=true`인 단어 수.
- 틀린수 = 범위 내 `word_progress`가 존재하고 `retired=false`인 단어 수 (회독 번호나 세션 중단 여부와 무관하게 "한 번이라도 틀렸고 아직 졸업 못 한" 단어는 전부 포함).
- 대기 = 범위 내 `word_progress`가 아예 없는 단어 수 (전체 - 맞은수 - 틀린수와 동일).
- "1회독이 끝났다"는 별도 이벤트가 아니라, 대기=0이 된 상태(범위 내 모든 단어가 최소 한 번은 판정됨)를 상태 요약 숫자로 간접 확인하는 것이다. 그 시점부터 회독 모드를 다시 시작하면 후보 풀은 자연히 틀린수(재도전 대기 단어)만 남는다.

## 9. 채점 로직 (Claude 연동)

- 입력: 단어(word), 사용자 답변(user_answer).
- Claude에게 다음을 판단하도록 요청:
  - 사용자 답변이 해당 단어의 한글 뜻을 (정확히 또는 유사하게) 맞췄는가, **또는**
  - 사용자 답변이 해당 단어를 문법적으로 올바르고 의미에 맞게 사용한 영어 예문인가.
  - 위 두 경우 중 하나라도 충족하면 정답으로 처리.
- 출력: `{ correct: boolean, feedback: string }` — `feedback`은 정답/오답 이유를 한 줄로 간단히 설명.
- `generateObject`(zod 스키마)로 구조화된 출력을 받아 파싱 실패 리스크를 없앤다.
- 자유 퀴즈/회독 모드 모두 동일한 채점 로직을 공유한다.

## 10. 에러 처리

- **Claude API 호출 실패/타임아웃**: 사용자가 입력한 답변은 그대로 유지한 채 에러 메시지와 "다시 채점하기" 버튼을 표시. 이 경우 `attempts`에 기록하지 않고, 회독 모드라면 `word_progress`도 변경하지 않는다(재시도 가능한 상태 유지).
- **DB 저장 실패**: 채점 결과는 이미 계산되었으므로 사용자에게는 그대로 보여주되, 저장 실패를 작은 경고로만 표시하고 퀴즈 진행을 막지 않는다.
- **Day 범위 내 단어 수 < 요청 문제 수** (자유 퀴즈) / **후보 풀 크기 < 요청 문제 수** (회독 모드): 있는 만큼만 출제하고 "N개로 진행합니다" 안내.
- **후보 풀이 0개** (회독 모드, 해당 범위 전체 졸업): 퀴즈를 시작하지 않고 "이 범위는 모두 완료했습니다" 안내와 함께 다른 범위 선택을 유도.

## 11. 테스트 계획

- 단어 무작위 선택 로직(Day 범위 필터링, 중복 없는 샘플링, 개수 부족 시 처리)에 대한 단위 테스트 — 자유 퀴즈/회독 모드 공통.
- 회독 상태 전이 로직 단위 테스트: 정답/오답에 따른 `status`/`round`/`missed_this_round`/`wrong_rounds`/`retired` 변화, 회독 번호 우선순위(작은 회독부터 소진) 규칙, 취약 단어(`array_length(wrong_rounds,1)>=3`) 판정, 후보 풀이 빈 경우 처리.
- 채점 함수의 프롬프트 구성 및 응답 파싱에 대한 단위 테스트(Claude 응답은 목으로 대체).
- 전체 플로우(모드 선택 → Day 범위/단어집 선택 → 퀴즈 진행 → 채점 → 기록 확인)는 Playwright(MCP)로 브라우저에서 수동/자동 확인. 회독 모드는 여러 세션에 걸친 이어하기(진행 상태 영속성) 시나리오도 확인.

## 12. 향후 고려 사항 (이번 범위 밖)

- 회독 간 시간 간격을 고려한 간격 반복(spaced repetition) 스케줄링.
- 단어 데이터 앱 내 업로드/편집 UI.
- 취약 단어만 모아서 별도의 집중 학습 모드 제공.
