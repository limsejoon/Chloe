# 영단어 퀴즈 웹앱 — PRD

- 작성일: 2026-07-19
- 상태: 초안 (사용자 리뷰 대기)

## 1. 개요 / 목적

이미 단어를 다 외운 학생(사용자 본인)이 40일치(Day 1~40, 총 1200개, Day당 30개) 영단어를 얼마나 알고 있는지 스스로 점검하기 위한 개인용 퀴즈 웹앱. 사용자가 Day 범위와 문제 수를 지정하면 해당 범위에서 무작위로 단어를 출제하고, 사용자가 한글 뜻 또는 영어 예문으로 답하면 Claude API가 정답 여부와 이유를 판정한다.

## 2. 목표 / 비목표

**목표**
- Day 범위(예: Day 3, 또는 Day 1~Day 10)와 문제 수(1~30)를 지정해 퀴즈를 시작할 수 있다.
- 자유 형식 답변(한글 뜻, 영어 예문 등)을 Claude가 채점하고 간단한 이유를 알려준다.
- 퀴즈 결과가 서버에 저장되어 나중에 다시 확인할 수 있다.

**비목표 (이번 범위에서 제외)**
- 로그인/계정/멀티유저 지원 — 본인 혼자 쓰는 도구.
- 앱 내 단어 업로드/편집 UI — 단어 데이터는 1회성 시드로 주입.
- 간격 반복(spaced repetition) 알고리즘, 오답 자동 재출제 스케줄링 등 학습 알고리즘 고도화.

## 3. 사용자 & 사용 시나리오

단일 사용자(본인)가 브라우저로 접속해:
1. Day 범위 선택 (단일 Day 또는 Day 1~Day 10 같은 범위) + 문제 수 입력.
2. "퀴즈 시작" → 해당 범위에서 무작위로 단어가 한 번에 하나씩 출제됨.
3. 자유 텍스트로 답변 입력 (예: "자동차", "카", 또는 "my car is not expensive.") 후 제출.
4. Claude가 정답 여부(O/X) + 간단한 이유를 즉시 보여줌.
5. 모든 문제를 마치면 세션 요약(몇 개 중 몇 개 정답) 표시.
6. "기록" 페이지에서 과거 세션들을 다시 볼 수 있음.

## 4. 아키텍처

- **프레임워크**: Next.js (App Router, TypeScript), Tailwind CSS, Vercel 배포.
- **DB**: Vercel Marketplace의 Neon Postgres. 스키마 관리는 Drizzle ORM.
- **AI 연동**: Vercel AI SDK를 통해 AI Gateway 경유로 Claude 모델 호출(`"anthropic/claude-..."` 형식의 모델 문자열). 채점은 `generateObject` + zod 스키마로 구조화된 JSON(`{ correct: boolean, feedback: string }`)을 받아 파싱 오류 없이 처리.
- **인증**: 없음 (본인 전용 개인 도구).

## 5. 데이터 모델

```sql
words
  id         serial PRIMARY KEY
  day        int NOT NULL          -- 1~40
  word       text NOT NULL         -- 예: "car"
  UNIQUE (day, word)

attempts
  id           serial PRIMARY KEY
  session_id   uuid NOT NULL        -- 한 번의 퀴즈(여러 문제)를 묶는 값
  word_id      int NOT NULL REFERENCES words(id)
  user_answer  text NOT NULL
  is_correct   boolean NOT NULL
  feedback     text NOT NULL
  created_at   timestamptz NOT NULL DEFAULT now()
```

- 단어 자체의 "뜻"은 저장하지 않는다 — 채점 시 Claude가 자체 지식으로 판단한다.
- `session_id`는 퀴즈 시작 요청(단어 선택 API/Server Action) 처리 시 서버에서 생성한 UUID로, 같은 퀴즈 회차에 속한 문제들을 하나로 묶는다. 별도의 `sessions` 테이블은 두지 않는다 (단일 사용자라 불필요).

## 6. 단어 데이터 시드

- 사용자가 텍스트 파일 제공 (Day별 구분, 표제어만 나열, 뜻 없음).
- 개발자(Claude Code)가 파일을 파싱해 1회성 시드 스크립트로 `words` 테이블에 삽입.
- 앱 내 업로드/편집 UI는 만들지 않는다. 향후 단어를 바꾸고 싶으면 시드 스크립트를 다시 실행.

## 7. UI/UX 흐름

**퀴즈 시작 화면**
- Day 범위 선택: "시작 Day"와 "끝 Day" 두 개의 select(1~40). 단일 Day를 원하면 둘을 같은 값으로 선택.
- 문제 수: 숫자 입력 필드 (1~30, 기본값 5).
- "퀴즈 시작" 버튼 → 선택한 Day 범위에 속한 단어들 중 무작위로 지정한 개수만큼 중복 없이 선택 (범위 내 단어 수보다 많은 개수를 요청하면 있는 만큼만 출제하고 화면에 안내 문구 표시).

**퀴즈 진행 화면**
- 한 번에 단어 하나씩 카드 형태로 표시 (예: "car").
- 자유 텍스트 입력창 (한글 뜻 또는 영어 예문 모두 허용) + "제출" 버튼.
- 제출 시 로딩 상태 표시 → Claude 채점 결과(정답 여부 + 이유)를 카드 아래 즉시 표시 → "다음 문제" 버튼으로 진행.
- 진행 상황 표시 (예: "3 / 5").

**결과 요약 화면**
- 세션 종료 시 "5문제 중 4개 정답" 같은 요약과, 문제별 O/X + 사용자 답변 + 피드백 리스트.

**기록(History) 페이지**
- 과거 세션 목록 (날짜, Day 범위, 정답 수/전체 문제 수).
- 세션 클릭 시 해당 세션의 문제별 상세(단어, 내 답변, 정답 여부, 피드백) 확인 가능.

## 8. 채점 로직 (Claude 연동)

- 입력: 단어(word), 사용자 답변(user_answer).
- Claude에게 다음을 판단하도록 요청:
  - 사용자 답변이 해당 단어의 한글 뜻을 (정확히 또는 유사하게) 맞췄는가, **또는**
  - 사용자 답변이 해당 단어를 문법적으로 올바르고 의미에 맞게 사용한 영어 예문인가.
  - 위 두 경우 중 하나라도 충족하면 정답으로 처리.
- 출력: `{ correct: boolean, feedback: string }` — `feedback`은 정답/오답 이유를 한 줄로 간단히 설명 (예: "정답입니다" / "car는 '자동차'라는 뜻이에요, 문장의 의미가 달라요").
- `generateObject`(zod 스키마)로 구조화된 출력을 받아 프리텍스트 파싱 실패 리스크를 없앤다.

## 9. 에러 처리

- **Claude API 호출 실패/타임아웃**: 사용자가 입력한 답변은 그대로 유지한 채 에러 메시지와 "다시 채점하기" 버튼을 표시. 이 경우 `attempts`에는 기록하지 않는다.
- **DB 저장 실패**: 채점 결과는 이미 계산되었으므로 사용자에게는 그대로 보여주되, 저장 실패를 작은 경고로만 표시하고 퀴즈 진행을 막지 않는다.
- **Day 범위 내 단어 수 < 요청 문제 수**: 있는 단어 수만큼만 출제하고 화면에 "해당 범위에 N개 단어만 있어 N문제로 진행합니다" 안내.

## 10. 테스트 계획

- 단어 무작위 선택 로직(Day 범위 필터링, 중복 없는 샘플링, 개수 부족 시 처리)에 대한 단위 테스트.
- 채점 함수의 프롬프트 구성 및 응답 파싱에 대한 단위 테스트(Claude 응답은 목으로 대체).
- 전체 플로우(Day 범위 선택 → 퀴즈 진행 → 채점 → 기록 확인)는 Playwright(MCP)로 브라우저에서 수동/자동 확인.

## 11. 향후 고려 사항 (이번 범위 밖)

- 오답 단어만 모아서 재출제하는 기능.
- 간격 반복 학습 스케줄링.
- 단어 데이터 앱 내 업로드/편집 UI.
