# 배치 채점 전환 — 설계 문서

- 작성일: 2026-07-20
- 상태: 사용자 승인 완료 (브레인스토밍 대화로 확정)
- 기반 문서: `docs/superpowers/specs/2026-07-19-vocab-quiz-design.md` (이하 "원본 스펙"). 이 문서는 원본 스펙의 §7~§10을 아래 내용으로 대체한다. 그 외 절(§1~§6, §11~§12)은 원본 스펙을 그대로 따른다.

## 1. 배경 / 동기

현재 구현(자유 퀴즈/회독 모드 모두)은 단어 하나를 풀 때마다 Claude API를 1회씩 호출해 즉시 채점한다. 문제 수가 많아질수록(예: 자유 퀴즈 최대 30개) API 호출 횟수가 그만큼 늘어나 비용이 커진다는 우려가 있다. 두 모드 모두 "여러 단어를 한 번에 다 풀고, 마지막에 한 번의 API 호출로 전체를 배치 채점"하는 방식으로 전환한다.

## 2. 변경 범위

- **자유 퀴즈**: 단어를 하나씩 플래시카드로 보여주되, 채점 없이 답만 로컬에 누적. 마지막 단어까지 다 풀면 한 번에 배치 채점.
- **회독 모드**: 동일한 플래시카드 흐름으로 전환. 단, 배치 채점과 구조적으로 충돌하는 **"틀린 단어를 같은 세션 안에서 다시 출제하는" 재출제(requeue) 기능은 폐지**한다. 틀린 단어는 "이번 회독에서 틀림"으로 기록되고, 다음 회독(다음 세션)에서 다시 만난다. 회독 번호 전이 규칙(원본 스펙 §8) 자체는 변경 없음 — 세션 내 즉시 재도전만 없어진다.
- 두 모드 모두 채점 백엔드는 "한 번의 API 호출로 세션 전체를 배치 채점"하는 방식 하나로 통일한다(청크 분할 없음 — 현재 문제 수 상한이 자유 퀴즈 30개, 회독 모드는 통상 5~10개 수준이라 한 번의 호출로 충분하다고 판단).

## 3. UI/UX 흐름 (원본 스펙 §7 대체)

**자유 퀴즈 — 진행 화면**
- 카드 하나씩 순서대로 제시. 답을 입력하고 "다음"을 누르면 **채점 결과를 보여주지 않고** 바로 다음 단어로 넘어간다(답은 로컬 상태에 누적만 됨). 빈 답변으로는 "다음"이 활성화되지 않는다(기존과 동일).
- 마지막 단어에서는 "다음" 대신 "채점하기" 버튼으로 표시. 누르면 배치 채점 API를 1회 호출하고, 완료될 때까지 로딩 상태를 보여준다.

**자유 퀴즈 — 결과 화면**
- 채점이 끝나면 전체 단어 목록을 O/X + 피드백과 함께 한 번에 보여준다(기존에는 세션 요약만 보여주고 상세는 기록 페이지에서 봐야 했지만, 배치 채점 특성상 결과 화면 자체가 이미 전체 상세를 가지고 있으므로 함께 표시). "N문제 중 M개 정답" 요약도 함께 표시.

**회독 모드 — 시작 화면**
- 원본 스펙 §7과 동일 (단어집/Day 범위/문제 수 선택, 현재 상태 요약 표시, 회독 번호 우선순위로 후보 풀 구성 — 변경 없음).

**회독 모드 — 진행 화면**
- 자유 퀴즈와 동일한 플래시카드 방식: 카드 하나씩, 채점 없이 답만 누적, 마지막에 "채점하기".
- **오답 시 세션 큐 재삽입 없음** (원본 스펙 §7의 "같은 세션 큐의 5~10문제 뒤쪽에 재삽입" 문구는 폐지). 세션 중에는 몇 회독인지 배지만 보여주고, 맞았는지 여부는 배치 채점 전까지 알 수 없다.

**회독 모드 — 결과 화면**
- 배치 채점 후: 이번 세션 정답/오답 수, 새로 졸업한 단어 수, 다음 회독으로 이월된 단어 수, 이번 세션에서 새로 취약 단어가 된 단어 목록을 모두 한 화면에서 보여준다(자유 퀴즈와 마찬가지로 단어별 O/X + 피드백 상세 포함).
- 세션 종료 후 갱신된 범위 전체 상태 요약도 함께 표시(원본 스펙과 동일).

## 4. 채점 로직 (원본 스펙 §9 대체)

- 기존 단건 함수 `gradeAnswer(word, userAnswer): Promise<{correct, feedback}>` 는 **삭제**한다.
- 신규: `gradeAnswers(items: {word: string; userAnswer: string}[]): Promise<{index: number; correct: boolean; feedback: string}[]>`
  - 프롬프트에 모든 `{word, userAnswer}` 쌍을 번호와 함께 나열하고, `generateObject` + zod 배열 스키마로 한 번에 판정을 받는다.
  - 응답 스키마는 각 결과 항목에 원래 입력의 `index`를 포함시켜, 입력 배열과 결과 배열을 순서에 의존하지 않고 정확히 매칭한다.
  - 반환된 결과 개수가 입력 개수와 다르거나 `index`가 입력 범위를 벗어나면 매칭 실패로 간주하고 에러를 던진다(모델 응답을 신뢰하지 못하는 상황을 조용히 넘기지 않음).
  - 정답 판정 기준(한글 뜻 일치 또는 올바른 영어 예문)은 원본 스펙 §9와 동일하게 유지.
- 자유 퀴즈/회독 모드 모두 이 배치 함수 하나를 공유한다(원본 스펙과 동일하게 채점 로직 자체는 공통).

## 5. 서버 액션 변경

**자유 퀴즈 (`src/app/actions/freeQuiz.ts`)**
- `startFreeQuiz`: 변경 없음.
- `submitFreeAnswer`(단건): **삭제**.
- 신규 `submitFreeQuizBatch(sessionId, items: {wordId, word, userAnswer}[])`: `gradeAnswers`를 1회 호출한 뒤, `attempts` 테이블에 결과를 한 번의 다중행 insert로 기록. 채점 성공 후 DB 저장에 실패해도 결과는 반환(§7 에러 처리 참고).

**회독 모드 (`src/app/actions/reviewQuiz.ts`)**
- `getReviewStatus`, `startReviewSession`: 변경 없음.
- `submitReviewAnswer`(단건): **삭제**.
- 신규 `submitReviewSessionBatch(sessionId, items: {wordId, word, userAnswer}[])`:
  1. `gradeAnswers` 1회 호출.
  2. 각 단어의 현재 `word_progress`를 일괄 조회하고, 단어별로 기존 순수 로직 `applyAnswer`(변경 없음)를 적용해 다음 상태 계산.
  3. `word_progress`(다중행 upsert)와 `attempts`(다중행 insert)를 각각 하나의 SQL 문으로 묶어 `db.batch([...])`로 원자적으로 저장(Task 12에서 도입한 `db.batch` 패턴 재사용 — `neon-http` 드라이버가 `db.transaction()`을 지원하지 않기 때문).
  4. 졸업 수/이월 수/신규 취약 단어 목록을 취합해 반환.
- **세션 큐 재출제 로직은 서버 액션에서도 완전히 제거된다** — `submitReviewSessionBatch`는 세션 중간 상태를 다루지 않고, 세션이 끝난 뒤 한 번에 전체를 처리한다.

## 6. 컴포넌트 변경

- 기존 `src/components/AnswerForm.tsx`(단건 채점 UI)는 두 플로우 모두에서 더 이상 쓰이지 않으므로 **삭제**.
- 신규 플래시카드 컴포넌트(가칭 `FlashcardInput`): 단어 표시 + 답변 입력 + "다음"/"채점하기" 버튼만 담당. 채점 API를 직접 호출하지 않고, 답변을 상위 컴포넌트의 로컬 상태 배열에 누적하는 역할만 한다.
- `FreeQuizFlow.tsx`/`ReviewQuizFlow.tsx`는 이 플래시카드 컴포넌트로 단어를 순회하고, 마지막에 배치 액션을 호출해 결과 화면을 렌더링하도록 재작성.
- `src/lib/queue.ts`(`requeueWrongAnswer`)와 그 테스트 파일은 더 이상 쓰이지 않으므로 **삭제**.

## 7. 에러 처리 (원본 스펙 §10 대체)

- **배치 채점 API 호출 실패**: `attempts`/`word_progress` 어디에도 기록하지 않는다. 결과 화면에 에러 메시지와 "다시 채점하기" 버튼을 보여주고, 누르면 같은 답변 목록으로 배치 채점을 재시도한다(사용자가 입력한 답변은 그대로 유지).
- **배치 채점 응답의 개수/인덱스 불일치**: 위와 동일하게 채점 실패로 처리(추측해서 매칭하지 않음).
- **채점은 성공했지만 DB 저장 실패**: 결과는 그대로 전부 보여주되, 화면에 작은 저장 실패 경고를 표시하고 진행을 막지 않는다(원본 스펙과 동일한 원칙, 범위만 단건→세션 전체로 확장).
- Day 범위/후보 풀 부족 관련 에러 처리(원본 스펙 §10의 나머지 항목)는 변경 없음.

## 8. 테스트 계획 (원본 스펙 §11 보강)

- `grading.ts`: `gradeAnswers`에 대한 단위 테스트로 교체 — mock된 배열 응답이 `index` 기준으로 올바르게 매칭되는지, 개수/인덱스 불일치 시 에러를 던지는지 검증.
- `reviewTransition.test.ts`/`reviewPool.test.ts`/`sampleRandom.test.ts`: 변경 없음 (순수 로직은 호출 방식만 "세션당 1회, 반복 적용"으로 바뀔 뿐 로직 자체는 그대로 재사용).
- `queue.test.ts`: 삭제 (대응하는 `requeueWrongAnswer`가 삭제되므로).
- 신규 배치 서버 액션(`submitFreeQuizBatch`, `submitReviewSessionBatch`)은 기존 단건 액션들과 동일한 방침으로 **자동 단위 테스트 없이 라이브 DB 검증**으로 확인한다(Server Action이라는 성격, 그리고 원본 프로젝트에서 이미 확립된 패턴을 따름).
- 전체 플로우(자유 퀴즈/회독 모드 각각 배치 채점까지 포함)는 Playwright(MCP)로 브라우저에서 확인.

## 10. 향후 고려 사항 (이번 범위 밖)

- 회독 모드에서 "틀린 것만 다시 풀기" 2단계 배치(같은 세션 안에서 틀린 단어만 모아 재드릴) — 이번에는 채택하지 않았지만 향후 필요시 별도 스펙으로 검토 가능.
- 문제 수가 크게 늘어날 경우(예: 50개 이상) 청크 단위 배치 분할 — 현재 문제 수 상한(자유 퀴즈 30개)에서는 불필요하다고 판단해 이번 범위에서 제외.
